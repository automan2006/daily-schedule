# 调用与平台

## 开始使用

在支持插件的宿主中打开“Daily Schedule”，按宿主提示安装，连接 Google Calendar 与 Todoist。先说“检查日历与待办连接，不创建内容”，再下达真实指令。

可以选择插件后直接说自然语言；支持 Skill 显式调用的环境也可使用 `$daily-planner`。

- “周五前交报告，优先级高。”——任务始终保留一个待办和日历展示，超过 24 小时用跨天周期条目，其他情况用单日条目或执行块。
- “明天下午三点到四点开会。”——只建 Calendar 日程，不生成 Todoist 待办，不需要勾选。
- “买电池。”——Todoist 无日期待办，Calendar 今天显示“未安排任务”。
- “周五前交报告，明晚七点到九点写。”
- “把写报告的时间改成晚上八点到十点。”
- “本周日之前完成课程报告。”——显示从今天到周日的全天周期条目。
- “报告截止日期延后两天，写作时间不变。”——延长周期条目，保留原执行时段。
- “报告完成了。”
- “删除下周三的组会。”——查找唯一匹配的该次日程后直接删除；匹配不唯一时只询问目标。
- “看看今天的任务、本周截止和逾期事项。”

## 四端分别验收

手机 ChatGPT、网页 ChatGPT、桌面 Codex 和本地 Codex 分别检查：插件或技能是否可发现、两个服务是否可查询、指定测试条目的写入和读回是否一致。某端没有插件入口或相关写入工具时应明确报告未通过，不能从另一端成功推断。

本地 Codex 可使用同一插件目录或通过宿主支持的技能安装机制加载 skills/daily-planner；仍需在该环境连接两个服务。不要仅复制 SKILL.md 后宣称完整安装，也不要为便于本地调用把授权令牌写进插件。

## 已知边界

- 没有后台进程、定时运行服务、外部变更监听或持续双向同步。
- 不负责自动改变用户已有 Todoist—Google Calendar 集成设置。若应用本身已将任务显示在日历中，创建手动时间块前检查重复来源，明确区分集成显示与插件创建的事件。
- 没有离线写入队列。断网时提供待执行内容；恢复后先查找是否已经成功再重试。
- 插件对用户明确指令直接执行，不额外设确认步骤。宿主平台自身的权限与审批提示仍由平台控制；技能不能关闭或绕过它们。
