# 任务日历展示：单日、跨天与执行时段

## 首先区分任务和日程

已经确定为会议、课程、预约、比赛或用户明确指定的日程，只建立 Google Calendar 普通 Event，绝不调用 Todoist 创建待办。时间明确不等于需要勾选完成；日程移动、结束、重复或取消也不产生任务。只有用户明确要求把某日程转为任务时才进行转换。

以下规则仅用于已经分类为任务的事项。默认一个 Todoist 待办，且 Calendar 必须有展示；只有用户针对本条明确要求“只放待办/不进日历”时例外。

## 选择展示形态

1. 硬截止距离基准严格超过 24 小时且未逾期：生成透明全天 period，保留原跨天规则。基准取明确任务周期开始时间，只给开始日期则取当地零点；未指定取当前时刻。截止仅有日期按该日结束计算。
2. 有完整执行时段：生成 execution 时间块；若同时符合跨天条件，允许 period 和 execution 并存，仍只有一个待办。
3. 既无 period 又无 execution：生成一个透明全天 date_task。日期优先级为明确计划执行日、明确开始日、截止日、本次收集日（今天）。即使任务无日期、截止不超过一天或恰好一天，也必须出现在 Calendar。
4. 没有日期时，标题使用“[未安排任务] 买电池”，描述写明“日历日期仅为收集展示日，尚未指定执行日期和截止日期”；Todoist 保持无 due/deadline。日历的展示日期不能冒充任务截止。

period 开始日为明确开始日或首次建立时的当天，显示至截止当天，API end_date=截止翌日。date_task 则 start_date=选定展示日，end_date=展示日翌日。精确截止只记在描述，不能伪造成执行时段。

逾期任务不生成反向周期，使用截止当天的 date_task 并标注逾期。用户明确开始日晚于截止时澄清日期；执行时间块缺少起止边界时只询问缺失信息，不能猜测时长。

## 日期计算工具

有 shell 时，可运行 [日期计算脚本](../scripts/task_period.py)：
```sh
python scripts/task_period.py --display --now 2026-10-15T12:00:00+08:00 --deadline 2026-10-15T17:00:00+08:00
python scripts/task_period.py --display --now 2026-10-15T12:00:00+08:00
```

第一例输出今天的 date_task；第二例没有截止，也输出今天的收集展示条目。可传 --planned-date、--start、--execution-start 和 --execution-end。--now 必须带时区偏移。脚本只计算任务表示、不负责自然语言分类、不写外部服务；不能把它用于纯日程来决定是否创建待办。

旧的不带 --display 的调用仍只计算 period 条件，eligible=false 只意味着没有跨天条带，不代表任务不进日历。默认中国时区无额外依赖；其他 IANA 时区须有时区数据库，缺失时不猜偏移。没有 shell 时按相同规则计算。

## Calendar 与关联

- period/date_task 使用 event_type=default、attendees=[]、transparency=transparent，显示为“有空”；execution 按明确时段建立。普通日程沿用用户实际忙闲安排，不套任务模板。
- 标题可用“[本周任务] 交报告”“[周期任务] 交报告”“[任务] 买电池”；没有日期用“[未安排任务]”。标题是展示文字，不凭标题推定任务身份。
- 描述保存已核实的 Todoist task ID、类型 period/date_task/execution、展示日期来源、周期原始开始日、真实执行日期和截止（若有）、优先级。Todoist 描述保存对应日历 ID/event ID 和返回链接；保留用户原文，不杜撰链接。
- 一个当前任务最多一个概览（period 或 date_task），可有多个明确的 execution。新增或重试按同任务 ID 和条目类型去重，不能因日历展示新增第二个待办。创建一个新 execution 后，不再另建冗余单日概览；已有历史概览不擅自删除。
- 无任务关联的纯 Calendar Event 不反向补建 Todoist。账户中既有的应用集成条目只有在类型与范围等价且可核实时复用，不能把普通日程当作任务投影。

## 修改与生命周期

- 改任务截止：period 保持原始开始日，调整排他结束日。date_task 只有日期来源是截止时才随截止移动；用户明确的计划执行日和 execution 不被覆盖。标题、优先级和完成状态同步到 period/date_task。
- 增加或修改计划执行日：移动按该日期展示的 date_task，不编造硬截止。直接移动收集条目仅表示改变日历展示，除非用户明确改变任务执行日期，否则不回写 Todoist due。
- 超过一天变成一天内：已有 period 可以缩短保留，不能出现 end_date<=start_date。新的短任务直接建立 date_task。
- 移除硬截止后：已确认由本插件建立的 period 改成按计划执行日展示的 date_task；无其他日期则保留原始收集日作为展示。优先更新同一事件为单日概览，保留一个日历展示及待办，不丢失任务。若已有 execution，则无需为缺少截止补建其他条目。
- 完成待办后，period/date_task 标题添加一次“已完成｜”，恢复未完成则去掉，不删历史记录。纯日程没有这个流程，不能要求勾选；Calendar 的标题标记不等于原生任务状态。
- 重复任务仅管理当前实例，完成后读取下一次真实执行日/截止并生成下一实例的必要日历展示，旧概览标已完成；不预建无限未来条目。
- 删除按明确指令范围执行，不因关联存在顺带删除未要求对象。局部失败保留成功项，报告真实 ID，下次修复缺项；不宣称后台自动同步。

## 生效范围

对本次创建或修改的任务应用新规则；更新插件和查询概览不批量迁移全部旧待办或删除过去误建的任务。用户明确要求补齐现有任务或清理误建条目时，再查询指定范围并处理。
