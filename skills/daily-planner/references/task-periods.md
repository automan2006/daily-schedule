# 跨天周期任务

## 创建条件与日期

- 对本次明确要求新建或修改的任务，取硬截止而非计划执行日期。未设置硬截止，不仅因 dueDate 在几天后就生成周期条目。
- 判断基准：用户明确给出任务周期开始时间时用它；只给开始日期时取该日当地零点；否则用本次调用的当前时刻。截止仅有日期时按当地当天结束计算；有精确时刻则保留精确时刻。
- 截止减判断基准严格超过 24 小时，并且没有逾期时，建立一个全天周期条目。恰好 24 小时不触发。用户明确要求“仅待办/不进日历”时尊重这次例外。
- 全天开始日期为明确的周期开始日，否则为首次创建周期条目当天；显示至截止当天，API end_date 必须为截止日的翌日。不能把截止日晚间变成单独的 00:00 定时事件。
- 例如：周二建立“周五前交报告”，显示周二至周五的全天条带；“本周日之前完成”显示到周日，end_date=下周一。不是把多项任务合并为一个总条目。
- 明确开始日晚于截止或缺少无法推导的截止时，询问缺失信息。已经逾期时不自动建立起止颠倒的事件；继续保留待办并报告逾期。

有 shell 时，可运行 [日期计算脚本](../scripts/task_period.py) 计算严格阈值及排他结束日期：

```sh
python scripts/task_period.py --now 2026-10-15T12:00:00+08:00 --deadline 2026-10-18
```

路径以技能目录为基准；可选 --start 和 --timezone。--now 必须有 UTC 偏移，其他不带偏移的日期时间按目标时区解释。该脚本仅输出计算结果，不写入任何应用；没有 shell 时按同一规则计算。默认中国时区无额外依赖，其他 IANA 时区需要运行环境提供时区数据库，缺失时不得猜测偏移。

## Calendar 的展示

- 建立普通全天日程（event_type=default），attendees=[]、transparency=transparent，显示为“有空”，不占用整周空闲时间。不要使用需要特殊账户能力的 focusTime。
- 标题：开始与截止都在本周时可用“[本周任务] 交报告”，跨周时用“[周期任务] 交报告”。标题是展示文字，关联类型必须另行记录。
- 描述保留用户原文，并记录 Daily Schedule 类型=period、Todoist task ID、原始周期开始日期、截止日期/精确时刻及优先级。待办中记录 period 的日历 ID、事件 ID 和已返回链接。
- 明确安排的“明晚七点到九点写报告”额外建 execution 时间块。一个任务最多一个当前周期条目，可以有多个明确要求的执行时段；不能为周期条目再新增一个 Todoist 待办。
- 创建前查找已有的同任务 ID、同周期条目。出现现成自动集成条目时只在可验证其周期范围与类型等价的情况下复用；普通截止日投影不等于跨天条目。

## 修改、完成与删除

- 调整任务截止时，读回关联 period，保持原始周期开始日，更新全天排他结束日期及描述中的截止。任务标题、优先级、完成状态也同步到 period。未请求修改执行时段时保留 execution。
- 已有 period 的截止缩短到 24 小时以内时，更新原条目，不因为阈值变化自动删除或重建。必须保证 end_date 晚于 start_date；若新截止早于原始开始日，应澄清新的起始日再改该周期，其他合法改动可单独报告。
- 任务移除硬截止后，不再有可表达的周期终点：如果该 period 确认由本插件自动建立，可随该明确修改删除这一个自动 period，保留待办和所有 execution，并报告；来源不明的不删。
- 完成待办后，原 period 标题前添加一次“已完成｜”，保留历史日期；恢复未完成时去掉该标记。Calendar 没有原生 Todoist 完成状态。
- 重复任务只管理当前周期；完成后先读回下一次截止，旧 period 标为已完成，下一次符合条件再建新 period。不预建无穷未来事件，不自动合并不同周期。
- 用户明确只修改 period 展示日期时，不反向更改任务硬截止；如果用户明确改的是任务截止，则按上面规则同步。删除仍按用户指令的明确范围执行，不因关联存在就顺带删除未要求的对象。
- 任一路径部分成功时，保留真实成功项，记录对应 ID，下次只修复缺失部分。不能宣称后台持续同步；用户直接在应用里改动后，要等下一次相关调用才会检查和修复关联。

## 生效范围

从本版本开始，对本次创建或修改的任务应用新规则；插件更新、查询概览不会扫描和批量迁移所有旧待办。只有用户明确要求“把现有本周任务补到日历”等操作，才在指定范围内查询并补建。
