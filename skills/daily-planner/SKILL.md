# Daily Schedule

使用中文，通过当前环境已授权的 Google Calendar 和 Todoist 工具完成操作。根据实际返回值报告结果；不要把生成计划当作已经写入。

## 首次使用与平台能力

- 默认时区 Asia/Shanghai，按调用时的当前时间解释相对日期，回复时展示实际年月日及必要的星期、时间。
- 按需查询 Todoist user_info、Calendar list_calendars，确认账号时区、目标与实际工具能力。时区不一致时，在写精确时间前消除歧义；不要修改账号设置。
- 默认 Todoist 收件箱和可写主日历；用户指定项目或日历时，先定位真实 ID。不要将 Todoist 自带 Calendar 视为 Google Calendar。
- 这个插件只在收到聊天指令时操作，每次读取服务最新状态。提醒由对应应用执行；不承诺关闭聊天后自动运行、监听外部变化或主动通知。
- 工具不存在、未连接或权限不足时，说清缺少哪个连接与哪个动作。可以提供待执行草稿，不声称已同步。每个平台分别验证；本地文件不会自动使手机端获得连接。
- 工具调用细节读取 [连接与字段](references/connectors.md)。平台使用读取 [调用与平台](references/platforms.md)。

## 识别与分流

先拆分一句话中的独立事项，再识别动作、目标、时间、截止日期、优先级、重复规则和提醒。

- **先确定日程还是任务**：用户明确说“日程/会议/课程/预约”等安排，或明确指定只当日程，优先按日程处理。具体起止时间不自动把事项变成任务；是否需要产出和勾选完成结合用户原意判断。“明晚七点到九点写报告”默认任务；“把明晚七点到九点写报告作为日程，不要待办”则只建日程。仍有实质歧义时只澄清分类。
- **日程**：会议、课程、预约、比赛、明确的活动安排等，仅在 Google Calendar 建立普通 Event。不调用 Todoist 新增、完成或恢复工具，不为日程补任务、复选框或勾选要求。查询、移动、重复设置及取消日程也不自动产生任务。日历中看到某个 Event 并不表示它是待办；没有已核实任务关联的日程禁止反向补建 Todoist。
- **所有任务**：强调产出或完成的事项，默认在 Todoist 保留一个可勾选待办，同时必须在 Google Calendar 有任务展示。无截止、短于一天、恰好一天的任务也不能仅写 Todoist。
- **任务如何显示**：有明确完整执行时段时建立 execution 时间块；硬截止距离判断基准超过 24 小时时，还保留 period 全天周期条目。既没有周期条目也没有执行块时，建立一个透明的单日全天 date_task 条目：优先用计划执行日/开始日，其次截止日，均未指定则用本次收集日（今天），标明“未安排任务”，不把收集日写成 Todoist 执行日期或截止。
- **跨天任务**：period 仍从明确开始日或创建当天延续到截止当天，截止日期只给日期则按当天结束计算；用户明确周期开始时间时从该时间判断，否则从当前时间判断，严格超过 24 小时。这只是选择日历展示形态的条件，不再是任务能否进日历的条件。详见 [任务日历展示](references/task-periods.md)。
- **任务及执行时间**：“周五前交报告，明晚七点到九点写”。始终只有一个 Todoist 待办，Calendar 建 execution；符合跨天规则时另建 period。已有 period 或 execution 时，不再额外建立冗余的 date_task。后续使用真实 ID 更新原记录。
- 单说“明天写报告”是明天计划执行的任务，建立 Todoist 待办和明天全天 date_task，不编造硬截止。“明天七点开会”是缺少必要时间信息的日程，只询问所需时间，绝不降级为待办。

- 不从闲聊、假设例子或计划建议推断写入意图。用户明确要求记录或已给出明确管理指令时直接执行。

## 时间与优先级

- Todoist 任务无日期则保留无日期，Calendar 用今天的透明全天收集条目展示并标注未安排；这不是编造截止。无优先级则 p4。用户说“最高/紧急”→p1，“高/重要”→p2，“中”→p3，“普通/低/未指定”→p4；明确 p1—p4 时按原值。
- 区分计划执行日期与最晚截止日期。日期级硬截止用受支持的 deadlineDate；精确到时刻的截止保存在描述中，同时用工具支持的时间字段表达提醒所需时刻。账户不支持硬截止字段时，在描述保留截止信息，并在没有其他执行日期的情况下用 dueString 表达，明确告知这种降级。
- 只有硬截止日期时，除 deadlineDate 外也用同日 dueString 保证可在当日待办中看到；已经指定独立执行日期时保留它，不用截止日期覆盖。
- “今晚/下午/尽快”等不提供精确时刻时，不自行填入时间。日期清楚的任务可保存日期或无日期；要建立精确日程或提醒时才询问缺少的时刻。
- 日程缺少必要的日期、开始或结束时间时询问。用户给出时长可据此计算结束时间；全天日程用日期表示，不伪造 00:00 的定时安排。
- “延期截止日期”改硬截止并保持记录截止的描述一致；只有原执行日期是随截止日期自动设置且能由关联记录证实时才同步移动它。用户另行指定的执行日期和日历时间块保持不变。有两种日期但只说“延期”时先问改哪一个。
- 提醒仅在用户要求时设置，保留工具/账户的默认提醒，不擅自增加通知。费用或账户限制导致不支持时说明，不承诺已开启。

## 按明确指令直接执行

1. 查询最新状态，定位条目 ID。新增前查找相近标题、日期和关联，避免重复；标题相同不自动当作同一条。已有唯一匹配且没有改动时返回已有记录。
2. 用户明确给出的新增、修改、延期、优先级调整、完成、恢复未完成和删除指令，单条或范围明确的批量操作均直接执行，不额外询问“是否确认/是否继续”，不先停在预览步骤。用户指令本身就是该次操作的授权。仅在无法定位目标、缺少必要时间、重复范围不明或工具无法表达请求时，询问最少的缺失信息。查询和建议不触发写入；用户要求采用建议后直接执行。
3. 修改只发送变化字段，保留其他日期、参与人、描述、标签和重复规则。任务的标题、相关日期、优先级或完成状态变化时，同步关联的 period/date_task；明确执行时段未改变时不移动 execution。日程修改只操作 Calendar，不补建待办。多个合理匹配时列出少量候选，选择后再改。
4. 建立或移动日程前检查占用，忽略被移动记录自身及透明条目。用户已明确给出目标时段时，按指令直接执行，并在结果中说明重叠，不因冲突再索要确认，也不移动其他日程。用户要求自动找空闲时间时避开冲突；没有满足约束的空闲时间才询问如何调整。
5. 明确的删除指令直接执行：先查询并定位真实 ID、范围和子任务影响，再删除指令覆盖的对象，结果中报告实际删除内容。无需先展示清单等待确认。单次日期明确的重复日程指向该次实例；“整个系列/全部重复”指向系列。无法确定目标、重复范围或是否包含未提及的子任务时，只澄清缺失信息。不顺带删除项目、关联待办或其他日程。
6. 多条新增或修改在目标与范围明确时直接处理；范围含糊才询问。对话中“全部”要解析成明确候选，不能默认为账号全部数据。
7. 操作后读回关键字段与关联。超时或结果不明时先查询再决定是否重试；最多重试一次已确定未生效的瞬时故障，认证和权限错误停止该路径。不要因一个应用失败重建另一个已成功对象。

## 跨应用关联

仅对已经分类为任务的事项，先确保一个 Todoist 待办，再建立 period（周期概览）、date_task（单日任务展示）或 execution（执行时段）所需条目。在日历描述记录任务 ID、类型及已核实链接，在待办描述追加该类型的日历 ID/event ID 和返回链接；保留用户原文，不杜撰 URL。一个当前任务最多一个概览（period 或 date_task），可有多个明确安排的执行时间块。纯日程不执行这套跨应用流程。

这是每次调用查询的关联信息，不是后台双向同步。跨应用操作不是事务：部分成功时保留成功项，报告未完成的关联或写入，下一次按实际 ID 修复。不要自动删除成功项来回滚。

移动执行时段不改变任务截止；修改任务截止要调整关联 period 的结束日期，但不改变 execution 时间块。完成任务不删除历史日程，关联的 period/date_task 标记“已完成”；恢复未完成时移除这个标记。纯日程没有待办完成步骤，不能要求勾选。取消日程不删除待办。用户明确要求同时处理时，按指定范围直接执行，包括删除；不额外确认。

## 重复与完成

- 重复事项保留开始日期、频率和用户指定的结束条件；周重复从实际对应星期开始，创建后检查首次出现时间。
- 移动重复任务的一次日期时，优先 reschedule_tasks，避免 update_tasks 的 dueString 清空重复规则。
- Calendar 修改重复事项前读原记录，区分本次、整系列、此次及以后；范围含糊先问。使用工具实际支持的作用域，不能以创建无关副本代替修改。
- 删除重复日程时，只有已核实的实例 ID 才能代表本次；主系列 ID 会影响整系列。工具无法安全表达指定范围则暂停该删除并说明。
- 标记完成、恢复未完成需要定位真实待办并同步其 period/date_task 标题。完成重复任务可能推进下一次日期，读回并解释；旧周期标记已完成，按下一次已核实执行日或截止建立下一任务展示，不预建无限未来条目。恢复能力受工具限制时不创建替代任务。日历周期的“已完成”仅是标题标记，不是 Calendar 原生任务状态。

## 结果回复

简短列出成功创建/修改/完成/删除的条目、所属应用、实际日期和必要优先级，提供返回的可用链接。未成功或仅保存草稿的事项单独列明，并说明下一步。查询概览按截止日期和优先级组织；分页读取完之前不得声称列出了全部事项。

行为验收用例见 [验收场景](references/acceptance.md)。只阅读用例不算通过真实写入测试；未经用户授权，不为测试创建或删除线上条目。
